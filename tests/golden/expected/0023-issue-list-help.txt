List issues, most recently updated first. Filters combine with AND; a repeated
--state or --state-type matches any of its values, a repeated --label all of them;
--any-label matches any of its values, --without-label none of them.
--query searches titles, descriptions and comments, ranked by relevance unless
--sort is given; Linear allows 30 searches a minute. With one --team, it searches
that team, as Linear's team search does.
--project and --milestone are looked up first, both in one request: one that finds
nothing fails with NOT_FOUND, a name more than one shares with AMBIGUOUS and its
candidates. Names match ignoring case; none needs no lookup.
--team falls back to LINEARCTL_TEAM, then to default-team in config.
--blocked and --blocking send Linear's hasBlockedByRelations and
hasBlockingRelations, and Linear decides what matches: a blocks relation counts
only while both of its issues are open (triage, backlog, unstarted or started).
A completed or canceled issue on either end does not count (measured
<DATE>); a duplicate-state one was not measured.
parent, relations and inverseRelations are in a row only when --fields names
them, as issue show has them (each side of a relation with its state); they
cost one more request per 250 rows, and one per issue with more than 250
relations.

Fields: id, identifier, title, priority, priorityLabel, url, createdAt,
updatedAt, dueDate, estimate, state, assignee, delegate, team, project, cycle,
projectMilestone, labels, parent, relations, inverseRelations

Usage:
  linearctl issue list [flags]

Examples:
  linearctl issue list --assignee me --state-type started --json
  linearctl issue list --team ENG --label bug --updated-since 7d --fields identifier,title --json
  linearctl issue list --query "login timeout" --limit 10
  linearctl issue list --project Q4 --limit 0 --fields identifier,parent,inverseRelations --json

Flags:
      --any-label NAME         only issues with label NAME (repeatable; any of)
      --assignee WHO           only issues assigned to WHO: me, none, or an email
      --attachment-url URL     only issues with an attachment at URL (e.g. a linked pull request)
      --blocked                only issues Linear's hasBlockedByRelations matches: open issues an
                               open one blocks (open: triage, backlog, unstarted or started)
      --blocking               only issues Linear's hasBlockingRelations matches: open issues that
                               block an open one
      --completed-since WHEN   only issues completed since WHEN: a date, an RFC 3339 time, 7d or 24h
      --creator WHO            only issues created by WHO: me, none, or an email
      --cursor CURSOR          continue after CURSOR (nextCursor from the previous page)
      --cycle CYCLE            only issues in cycle CYCLE: current, next, previous, a number, a UUID
      --delegate WHO           only issues delegated to the agent WHO (name, email, me, any, none)
      --due-after DATE         only issues due on or after DATE
      --due-before DATE        only issues due on or before DATE (<DATE>)
      --fields FIELDS          return only these comma-separated FIELDS (see Fields above)
  -h, --help                   help for list
      --id ISSUE               only the issue ISSUE (ENG-123 or a UUID; repeatable); one not
                               found is a problem (exit 3)
      --include-comments       with --query, also match the text of comments
      --label NAME             only issues with label NAME (repeatable; all of)
      --limit N                show at most N items; 0 for all (default 25)
      --milestone MILESTONE    only issues in project milestone MILESTONE: its UUID or name
                               (none: in no milestone); with --project, one of that project's
      --priority PRIORITY      only issues of PRIORITY: 0-4 or none, urgent, high, medium, low
                               (repeatable, any of)
      --project PROJECT        only issues in project PROJECT: its URL, slugId, UUID or name
                               (none: in no project)
      --query TEXT             full-text search for TEXT
      --reverse                reverse the order of --sort
      --sort FIELD             FIELD: updated (default), created, priority, due-date, title, state
      --state NAME             only issues in workflow state NAME (repeatable; any of)
      --state-type TYPE        only issues whose state is of TYPE (repeatable): triage, backlog,
                               unstarted, started, completed, canceled, duplicate
      --team KEY               only issues of team KEY (e.g. ENG; repeatable, any of)
      --updated-since WHEN     only issues updated since WHEN: a date, an RFC 3339 time, 7d or 24h
      --view VIEW              only issues in Linear's saved custom view VIEW (a name or its id)
      --without-label NAME     only issues without label NAME (repeatable; none of)

Global Flags:
      --demo        use a built-in fictional workspace: no key, no network; or LINEARCTL_DEMO=1
      --json        print one JSON document on stdout
      --meta        add meta (requests sent, rate limit left) to --json; or LINEARCTL_META=1
      --timeout N   give up on a network request after N seconds (default 30)

Exit codes: 0 ok, 1 failed, 2 usage, 3 partial, 4 busy, 5 auth (no API key, or
Linear rejected it), 6 rate-limited (retry after retryAt), 7 conflict (it changed since
you read it; read it again)
