Show a project: its description, overview (content), status, health, documents,
milestones and issues. Documents are read in full; issues up to --issues, and
--all-issues reads every one, 250 a request.
PROJECT is a linear.app project URL, its slugId (the hex the URL ends with), a UUID,
or its exact name.

Fields: id, name, slugId, url, description, content, status, lead, startDate,
targetDate, progress, health, createdAt, updatedAt, teams, documents,
projectMilestones, issues

Usage:
  linearctl project show PROJECT [flags]

Examples:
  linearctl project show https://linear.app/acme/project/q4-launch-0527ca4c9128
  linearctl project show "Q4 launch" --issues 100 --fields name,content,issues --json
  linearctl project show "Q4 launch" --all-issues --fields name,issues --json

Flags:
      --all-issues      include every issue, however many (overrides --issues)
      --fields FIELDS   return only these comma-separated FIELDS (see Fields above)
  -h, --help            help for show
      --issues N        include the first N issues; 0 for none (default 50)

Global Flags:
      --demo        use a built-in fictional workspace: no key, no network; or LINEARCTL_DEMO=1
      --json        print one JSON document on stdout
      --meta        add meta (requests sent, rate limit left) to --json; or LINEARCTL_META=1
      --timeout N   give up on a network request after N seconds (default 30)

Exit codes: 0 ok, 1 failed, 2 usage, 3 partial, 4 busy, 5 auth (no API key, or
Linear rejected it), 6 rate-limited (retry after retryAt), 7 conflict (it changed since
you read it; read it again)
Run 'linearctl describe' for every command as JSON.
