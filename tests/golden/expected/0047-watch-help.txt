Stream changes to the issues a filter matches. With --json each line is one event:
  ready      {mode, since, known, everything}: up to date from since
  upsert     {issue}: an issue that matches, in issue list's row shape
  remove     {id, identifier, reason}: it stopped matching; reason is filter,
             archived or deleted
  heartbeat  {at, mode, rateLimit}: every --heartbeat seconds
  gap        {from, to, reason}: the stream was down (reconnect) or fell back
             to polling (fallback); what changed meanwhile follows as upserts
It runs until interrupted (exit 130) or a request fails, which ends it with the
usual exit codes (5 auth, 6 rate-limited, 1 failed) and a last {error} line.

Linear's subscriptions name the changed issues; linearctl checks each batch
against the filter with one request (at most one per 2 s) and reconciles every
--reconcile seconds. --mode poll asks Linear every --poll-interval seconds instead.
Removes are reported for issues known to match: up to 2,500 found at start, and
any since; beyond that (everything: true) every non-matching change is a remove.

Fields: id, identifier, title, priority, priorityLabel, url, createdAt,
updatedAt, state, assignee, delegate, team, project, cycle, projectMilestone,
labels

Usage:
  linearctl watch [flags]

Examples:
  linearctl watch --team ENG --json
  linearctl watch --assignee me --state-type started --since <TIME> --json

Flags:
      --any-label NAME       only issues with label NAME (repeatable; any of)
      --assignee WHO         only issues assigned to WHO: me, none, or an email
      --attachment-url URL   only issues with an attachment at URL (e.g. a linked pull request)
      --cycle CYCLE          only issues in cycle CYCLE: current, next, or a cycle number
      --delegate WHO         only issues delegated to the agent WHO (name or email; any; none)
      --fields FIELDS        return only these comma-separated FIELDS (see Fields above)
      --heartbeat N          print a heartbeat every N seconds (default 30)
  -h, --help                 help for watch
      --label NAME           only issues with label NAME (repeatable; all of)
      --milestone NAME       only issues in project milestone NAME (none: in no milestone)
      --mode MODE            MODE: auto (subscribe, else poll), subscription, poll (default "auto")
      --poll-interval N      when polling, ask Linear every N seconds (default 60)
      --priority PRIORITY    only issues of PRIORITY: 0-4 or none, urgent, high, medium, low
                             (repeatable, any of)
      --project NAME         only issues in project NAME
      --reconcile N          with subscriptions, catch up on missed changes every N s (default 300)
      --since WHEN           first replay changes since WHEN (a date, RFC 3339 time, 7d, 24h)
      --state NAME           only issues in workflow state NAME (repeatable; any of)
      --state-type TYPE      only issues whose state is of TYPE (repeatable): triage, backlog,
                             unstarted, started, completed, canceled, duplicate
      --team KEY             only issues of team KEY (e.g. ENG; repeatable, any of)
      --updated-since WHEN   only issues updated since WHEN: a date, an RFC 3339 time, 7d or 24h
      --without-label NAME   only issues without label NAME (repeatable; none of)

Global Flags:
      --demo        use a built-in fictional workspace: no key, no network; or LINEARCTL_DEMO=1
      --json        print one JSON document on stdout
      --meta        add meta (requests sent, rate limit left) to --json; or LINEARCTL_META=1
      --timeout N   give up on a network request after N seconds (default 30)

Exit codes: 0 ok, 1 failed, 2 usage, 3 partial, 4 busy, 5 auth (no API key, or
Linear rejected it), 6 rate-limited (retry after retryAt), 7 conflict (it changed since
you read it; read it again)
