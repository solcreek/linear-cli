Answer linearctl invocations over stdin and stdout, for a program that makes many
calls (a TUI, a long agent session). One process serves them all: no start-up, no
new TLS connection, no Keychain read per call.

Each line on stdin is a request:   {"id": ANY, "argv": ["issue", "list", "--json"],
                                    "stdin": TEXT (optional)}
Each line on stdout answers one:   {"id": ANY, "exit": N, "result": JSON|null,
                                    "stdout": TEXT|null, "stderr": TEXT}
argv is what follows linearctl on a command line; exit and the JSON in result are
exactly what that command line would give (result is null when it printed text,
which is then in stdout). stdin is that command's standard input, so - as a file
(--json-input=-, --body-file=-) reads it; "" is an empty one. Without stdin, - is
refused: serve's own stdin carries requests. A malformed line is answered with
exit 2; watch and serve are refused.

Requests run one at a time, in order. With --concurrency N, up to N run at once
and answers come as each finishes: match them by id. They share one key, one
connection pool and Linear's one rate budget; a request Linear limits answers
exit 6 like any other. Nothing orders two writes: send the second after the
first one's answer when it must come after. serve ends when stdin closes and
every request has its answer (exit 0).

Usage:
  linearctl serve [flags]

Examples:
  printf '{"id":1,"argv":["issue","list","--json"]}\n' | linearctl serve --stdio

Flags:
      --concurrency N   run up to N requests at once (at most 32), out of order (default 1)
  -h, --help            help for serve
      --stdio           read requests on stdin, answer on stdout

Global Flags:
      --demo        use a built-in fictional workspace: no key, no network; or LINEARCTL_DEMO=1
      --json        print one JSON document on stdout
      --meta        add meta (requests sent, rate limit left) to --json; or LINEARCTL_META=1
      --timeout N   give up on a network request after N seconds (default 30)

Exit codes: 0 ok, 1 failed, 2 usage, 3 partial, 4 busy, 5 auth (no API key, or
Linear rejected it), 6 rate-limited (retry after retryAt), 7 conflict (it changed since
you read it; read it again)
Run 'linearctl describe' for every command as JSON.
